## 1. Objective
Backend nạp nhiều mô hình cùng lúc; admin gõ một câu và thấy PhoBERT, SVM (và LR/NB nếu có) chấm điểm cạnh nhau — điểm trình diễn chính khi bảo vệ.

## 2. Context
BOI_CANH mục 9.2 T07; ARCHITECTURE 2.6.

## 3. Scope
### Allowed Scope
- Tách `classifier.py` thành registry: mỗi model có `name`, `version`, `predict(text) -> (is_negative, score)`.
- `.env`: `ACTIVE_MODEL` (mặc định `phobert`), `SKLEARN_MODELS=svm:models/baselines/svm_A.joblib,lr:...`.
- `POST /api/admin/predict {text}` → `[{model, version, label, score, ms}]` (require_admin).
- `/api/health` thêm `models: [{name, loaded, error}]`, `active_model`.
- Trang `/quan-tri/so-sanh-mo-hinh`: ô nhập, nút "Chấm điểm", bảng kết quả, 5 câu mẫu bấm nhanh (có câu "lê thê").
- Thêm `scikit-learn`, `joblib` vào `requirements-ml.txt` (đã được phép).

### Out of Scope
- Đổi `normalize()`. Admin đổi `ACTIVE_MODEL` trên giao diện (chờ Q3).

## 4. Thiết kế
- Mọi model nhận cùng đầu vào `normalize(text)` (giữ `_prepare` hiện có cho PhoBERT).
- SVM không có xác suất → `score` = sigmoid(decision_function); ghi rõ trong model card / `CONG_NGHE.md`.
- Thiếu file joblib hoặc lỗi nạp → bỏ qua model đó, `/api/health` báo `loaded:false, error:"..."`, web vẫn chạy.
- `ACTIVE_MODEL` trỏ tới model không nạp được → fallback `phobert`, rồi `keyword`, ghi log.
- `comments.model_name` lưu tên model active (`phobert`/`svm`/...).
- Mock: `api.admin.predict` trả điểm giả lập từ bộ từ khóa, đánh dấu `model: "mock"`.
